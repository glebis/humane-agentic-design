Four generated pages, twelve colour pairs each, six of them genuinely failing. Eight reviews, each run blind in its own directory with no access to the answer key. Half were told to use humane:review; half got a competent but unstructured “review this thoroughly and find the real problems”. Same model, same budget, both arms.

The result favours the skill on every metric that moved. It also required two corrections to the measuring instrument along the way — one of which reversed the apparent conclusion, and one of which I found only because a number disagreed with what I expected. Both are documented below, because a report on whether a method is honest cannot itself be selective.

1 · The setup ↑

Ground truth is arithmetic, not opinion — a pair either clears the bar or it does not.

The obvious way to run this eval is to produce both reviews and ask a model which is better. That is circular: the judge reads the skill’s own vocabulary — its severity scale, its Not reviewed result, its evidence locators — and rewards the arm that matches the rubric it was handed. It measures conformance, not improvement.

So no judgement enters the ground truth. Each fixture is generated with twelve foreground/background pairs, and every pair is measured by dtokens/contrast.py — the same code the design-tokens skill runs in production. A pair is a planted defect if and only if that program says it fails. Nothing is asserted by hand.

Blinding. Each arm received a directory containing fixture.html and nothing else. The manifest was never copied there.

Control quality. The unaided prompt asks for a rigorous review and warns that missing a real defect is worse than being verbose. Not a strawman.

The author reviewed neither arm. Knowing the answer key disqualifies you from being a subject.

The disagreement pairs. WCAG and APCA do not rank colour the same way. #2174a7 on #f5f3ef is a blue link on off-white: 4.60∶1, which clears the familiar 4.5∶1 bar, and APCA 67.7 against a floor of 75 — a real failure. Two of every six planted defects are of this kind. They are the defects a reviewer working from memory waves through, and the reason the fixture is not built from obvious grey-on-grey alone.

Mean across four seeds, all four measures on one 0–1 rate axis.

The interesting number is not recall — it is recall together with precision. Recall is trivially maximised by reporting everything, and precision by reporting nothing. A reviewer that improves one at the other’s expense has changed how wide a net it throws, not how well it knows where the fish are.

Both arms were free to carpet-bomb. The control largely did: 3.25 invented findings per run against 0.75, while still missing a fifth of the real ones. The skill arm found more with less noise, which is the only shape of result that distinguishes calibration from volume.

Routing. 0.70 against 0.00. The control never attributes a finding to an owning skill because it has no ownership model — this metric measures something the skill has and the control structurally lacks, so read it as a description, not a defeat.

Consolidation. The skill arm reports one root cause per row, listing every affected location. That nearly broke the scorer — see §4.

Invented findings per run — a count, so it is drawn separately rather than sharing an axis with the rates above. The control invented more on every seed.

4 · Fixing the instrument ↑

Two scorer bugs. The first inverted the result; the second was found while chasing a number I disliked.

Bug one: consolidation counted as failure. The scorer attributed each finding to a single best-matching pair. But the skill requires one root cause to be one row listing every affected location — so the skill arm consolidated six failing pairs into two rows, and the scorer read that as having missed four defects it had just named. The first run therefore read: with 0.33, without 0.67. The skill makes reviews worse. Corrected, the same two reports read 1.00 and 0.83.

Bug two: locator match ≠ subject matter. Every element in the fixture is a pair-NN, so any finding citing any element matched a pair and was classified as a contrast finding. A dead-link report on pair-06 scored as having detected that pair’s contrast defect. This inflated control recall from a true 0.79 to an apparent 0.92, and counted the skill arm’s layout and copy findings as contrast padding — penalising breadth, rewarding narrowness.

What caught bug one. An ambiguous counter that had no purpose except to surface findings matching more than one pair. It was not built to catch this.

What caught bug two. A control arm scoring 1.00 where the hypothesis predicted failure — investigated because it was surprising.

Disclosure. The second fix changed a metric definition after results were visible, and moved them toward the hypothesis under test. The bug is real and independently describable, and is tested in both directions. But it was found while investigating a number that disagreed with a prediction, and a fair reading is that agreement would have drawn less scrutiny. Anyone weighing these numbers should know that. It is recorded in the commit message as well as here.

5 · What this does not show ↑

One domain, four trials, and the metric that mattered most never fired.

The honesty metric never fired. false_clear — asserting a domain is Clear while it holds real defects — was the metric this harness was built around, and it scored 0 for both arms on all four seeds. That is a limitation of the fixture, not a virtue of either arm: a contrast-only page invites every reviewer to look at contrast, so nobody had the opportunity to falsely declare a domain clean.

Scope. Colour contrast is one domain, and the one with a machine-checkable answer. Structure, copy, task completion, and de-slop are most of the method and none of them are measured here. Reporting this as a grade for the method would fail the same honesty guard the skills impose on themselves.

Next. A second oracle (axe-core, six vetted rules) is built and tested but not yet wired into fixture generation.

Then. A fixture with a domain that cannot be checked from the artifact at all — the only way false_clear gets a chance to fire.

And. More trials per seed. Control recall varied 0.67–1.00 across four runs; that is noise, not a measurement.
