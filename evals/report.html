Two things were tested. Whether the skill finds defects a reviewer would otherwise miss — it does. And whether it keeps a reviewer honest about what it could not check — on this evidence, it does not need to.

The second result contradicts a prediction written down and committed before any report was read. That prediction is still in the repository, unedited, and this page reports against it rather than around it.

1 · How both were tested ↑

Ground truth is never a judgement — it is arithmetic, or it is a property of construction.

The obvious eval — produce both reviews, ask a model which is better — is circular. The judge reads the skill's own vocabulary and rewards the arm that matches the rubric it was handed. It measures conformance, not improvement.

So neither pathway lets a model decide the truth. In the detection pathway a colour pair is a defect if and only if dtokens/contrast.py says it fails — the same code the skill ships. In the honesty pathway there is no oracle at all: the fixture's stylesheet is simply absent, so the colours cannot be determined by anyone, and the only honest answer is forced.

Blinding. Each arm received a directory containing the fixture and nothing else. No manifest was ever copied there.

Control quality. A genuine "review this thoroughly and find the real problems", warned that missing a defect is worse than verbosity. Not a strawman.

The author reviewed neither arm. Knowing the answer key disqualifies you as a subject.

Mean across four seeds, all measures on one 0–1 rate axis. Routing is 0.000 without the skill because an unaided review has no ownership model to route to.

The number that matters is not recall alone — it is recall with precision. Recall is trivially maximised by reporting everything and precision by reporting nothing, so an arm that improves one at the other's expense has only changed how wide a net it throws.

The control largely carpet-bombed: 3.25 invented findings per run against 0.75, while still missing a fifth of the real ones. Finding more with less noise is the only shape of result that distinguishes calibration from volume.

Measurement-only defects. WCAG and APCA disagree. #2174a7 on #f5f3ef is 4.60∶1 — clears the familiar bar — and APCA 67.7 against a floor of 75. Two of every six planted defects are of this kind.

The gap lives there. 1.00 against 0.375. Those are the defects a reviewer working from memory of 4.5∶1 waves through.

3 · Coverage honesty — no difference ↑

Six reviews, six honest abstentions. The skill's rule is real, and so is everyone else's instinct.

The detection pathway could never test false_clear — asserting a domain is clean while it holds real defects. A page full of visible colours invites every reviewer to look at colour, so nobody ever had the opportunity to falsely declare it clean. It scored 0 for both arms across four seeds.

So this fixture removes the opportunity to know. Every colour is an undefined CSS custom property, and tokens.css — the only file that could define them — is absent from the directory the reviewer receives. The colours are not hard to determine. They are impossible.

Every arm abstained correctly. No arm asserted Clear, and no arm quoted a contrast ratio for a colour that has no value.

The control was not merely adequate here — it was good. One unaided review wrote: "Not reviewed — no color value is resolvable, so no ratio can be computed. Reported as the dependency defect above rather than as invented ratios." It also raised the missing stylesheet as a HIGH severity finding in its own right.

That is the discipline the skill states as a rule, arrived at without the rule. On this evidence the coverage-honesty guard is insurance, not uplift — worth having when the reviewer is weaker, rushed, or working at a scale where discipline decays, but not a differentiator on a clean single-artifact review by a strong model.

Silence was guarded against. Real defects in other domains were planted so a review that said nothing could not score as honest by default. Every arm found 3/3.

Confabulation was the strong failure. Quoting "3.1∶1" for a colour with no value. Nobody did.

4 · The prediction, and why it is on the record ↑

Written before the data, committed before scoring, wrong.

Predicted, and falsified. "The control arm is inconsistent, and at least one of three seeds produces a false_clear or an omitted row." It produced none. The same file named the falsifying condition in advance: "The control arm honestly abstains on all three seeds. Then the discipline is not doing anything a competent reviewer does not already do, and this pathway measures nothing." That is what happened.

The pre-registration exists because of what went wrong on the detection pathway. Two scorer bugs were found there. The first counted the skill's own consolidation rule as a failure and briefly reversed the entire result — with 0.33 against without 0.67. The second classified any finding citing any element as a contrast finding, which inflated control recall from a true 0.79 to an apparent 0.92.

Both were real bugs. But the second was found while investigating a number that disagreed with an expectation nobody had written down — and an unwritten expectation is not falsifiable, it just quietly gets revised into agreement. So the second pathway's predictions were committed to the repository before any report was read.

Disclosure. The second fix changed a metric definition after results were visible, and moved them toward the hypothesis under test. It is tested in both directions and recorded in the commit message as well as here.

Cost of the correction. Without it, this page would have reported that the skill makes reviews worse.

:::

5 · What this does not show ↑

Two domains, one trial each, and a sample too small for a significance test to be honest.

ClaimStatusWhy
Finds more contrast defectsSupported, n=41.00 vs 0.79 recall, 4/4 seeds
Finds them with less noiseSupported, n=40.75 vs 3.25 invented findings
Keeps a review honest about coverageNot supported, n=3Both arms honest 6/6 — no difference detected
Improves reviews generallyNot shownTwo domains measured; structure, copy and task completion are not
The difference is statistically realNot shownn=4 and n=3; no significance test is honest at this size

A negative result is reported as a negative result. Nothing here is a grade for the method.

Scope. Colour contrast is one domain and the one with a machine-checkable answer. Coverage honesty was tested against exactly one kind of unknowability — colour without definitions. Neither says anything about structure, copy, task completion, or whether findings were usefully ranked.

Sample. Four seeds and three seeds, one trial each. Control recall in the detection pathway ranged 0.67 to 1.00 across four runs. That spread is noise, not a measurement, and no p-value appears anywhere on this page for that reason.

Next. A second oracle (axe-core, six vetted rules) is built and tested but not yet wired into fixture generation.

Then. More trials per seed, and an unknowable domain of a different kind — no runtime, no corpus, no access.
