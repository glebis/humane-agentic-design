# Art direction

How the panels are dressed once the mode and layout are chosen: detail, text,
taglines, imagery, mockups, color, and how to use references.

## Premium detail language

Small page numbers · tiny footer labels · precise alignment marks · construction
lines · subtle crosshair grids · thin rules · browser bars · rounded rectangles ·
image masks · soft shadows · low-opacity texture · halftone image treatment · one
highlighted word · one accent chip · one strong icon state.

**Do not overuse them.** Premium detail rewards looking closer; it does not
announce itself. Spend the boldness in one place and keep everything around it
quiet.

## Text rules

Use very little text — it is the single most common way a generated board looks
cheap, because small text renders as mush.

| Good text | Bad text |
| --- | --- |
| Brand name | Long paragraphs |
| One tagline | Tiny fake body copy |
| One URL | Long menu lists |
| One command | Lorem ipsum |
| 2–5 section labels | Dense explanations |
| Short UI chips | Anything unreadable at output size |

Text must be large enough and sparse enough to render cleanly.

## Tagline style

Short and specific. A tagline is a promise, not a mission statement.

**Good:** "What will you build today?" · "Nothing random." · "Your network. Our
watch." · "Build better." · "On guard." · "Every mission under control." ·
"Everything operators need." · "Clarity builds confidence."

**Avoid:** generic corporate slogans, long marketing copy, buzzword soup,
inspirational fluff.

## Image direction

Images must feel art-directed, and must match the palette and the metaphor.

**Use:** cinematic mountains · dusk skies · landscapes with brand overlays ·
halftone clouds · CRT screen scenes · dark product closeups · dramatic object
crops · textured paper backgrounds · moody architecture · abstract but controlled
visual systems.

**Avoid:** generic stock people · random office photos · cliché robot imagery ·
overbusy scenes · imagery unrelated to the brand idea.

## Mockup direction

Mockups are **identity applications, not feature demos**.

**Use:** browser chrome · URL bar · terminal window · command prompt · app icon ·
phone corner crop · card stack · badge · seal · folder · UI chips · dashboard
fragment · input bar · product label.

**Avoid:** full fake dashboards dense with data · cheap glossy mockups · device
overload · busy app screens · excessive icons.

## Color discipline

One dominant palette: a base color, a primary accent, a secondary accent, and
neutrals.

Reference-grade combinations:

- black + cyan + muted coral
- black + red + cream + blue
- forest green + lime + fog gray
- navy + white + steel
- ivory + deep blue + red + gold
- black + lilac + soft purple
- black + amber + red
- charcoal + white + pale blue

Rules: accents repeat across panels · no rainbow unless requested · no generic
purple-blue "AI glow" unless it genuinely fits · one accent can carry the whole
system.

## Using references

When the user supplies reference images, extract the **behavior**, not the
content: layout rhythm, grid style, spacing, typography scale, visual density,
logo placement, quantity of text, image treatment, accent-color logic, and how
the brand system repeats.

Never copy the exact logo, brand name, composition, slogan, or any unique visual
asset. References are a quality bar, not a template.
